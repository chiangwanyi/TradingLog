### 环境

- `uv 0.12.17`（`C:\Users\jiang\.local\bin\uv`），Python 3.13 由 uv 管理。
- 初始化命令：`uv init server --app --name tradinglog-server --python 3.13 --managed-python --vcs none --no-description`
  - 注意：`uv init --app` 默认生成 **src-layout + uv_build 打包后端**（不是扁平 main.py），包名按项目名推导为 `tradinglog_server`。

### 关键决策

- **包名改为 `app`**（导入路径 `app.xxx` 更简洁）。因为包名与项目名不一致，必须在 `pyproject.toml` 显式声明：
  ```toml
  [tool.uv.build-backend]
  module-name = "app"
  module-root = "src"
  ```
  否则 uv_build 找不到 `src/tradinglog_server/` 会构建失败。
- `--vcs none`：避免生成嵌套 git 仓库（根目录统一管理）。
- 分层结构：`src/app/main.py`（应用工厂 create_app + ASGI 实例）、`core/config.py`（pydantic-settings 配置中心）、`api/v1/router.py`（路由汇总）、`api/v1/endpoints/*.py`（业务接口，目前只有 health）、`tests/`（conftest + 冒烟测试）。
- 依赖：运行时 `fastapi` / `uvicorn[standard]` / `pydantic-settings`；开发依赖走 PEP 735 的 `[dependency-groups].dev`：`pytest` / `ruff` / **`httpx2`**。
  - 注意：starlette 1.7 起 `starlette.testclient` 已弃用 `httpx`，改用 **`httpx2`** 可消除弃用告警；`httpx` 已从 dev 依赖移除。
- 新增 `server/.gitignore`（忽略 `.venv/`、`__pycache__/`、`.env`、各类缓存），`.env.example` 提交、`.env` 不提交。

## 新增「交易截图相册」功能（前后端全链路）

用户需求：相册含多图集 → 图集含多图 → 图含多条批注；图集按交易时间排序；新建图集需交易时间（精确到分）+ 标的；图片支持剪贴板粘贴与文件上传、按上传时间排序；横向查看器 + 左右切换 + 底部缩略图条；查看/批注两种模式；批注分点批注与矩形批注；**序号在同一图集内跨图片统一编号**。

### 架构决策（已与用户确认）

存储方案选 **后端 API + SQLite + 服务器文件**（另两个备选是纯前端 IndexedDB、图片 base64 入 DB，均被否）。

### 后端（server/）

新增依赖：`python-multipart`（UploadFile 解析）、`pillow`（尺寸读取 + 缩略图）。

新增文件：`core/db.py`（连接 + 三张表 schema）、`core/errors.py`（领域异常）、`schemas/{album,image,annotation}.py`、`services/{albums,images,annotations,common}.py`、`api/v1/endpoints/{albums,images,annotations}.py`、`tests/test_albums.py`。

关键设计：

- **数据库用标准库 `sqlite3`**，不引 ORM。元数据只三张表、查询简单，够用且零额外依赖。`get_conn()` 是 contextmanager，按请求建连、开启 WAL、`PRAGMA foreign_keys=ON`。
- **数据目录** `server/data/`（`Settings.data_dir`，默认 `SERVER_ROOT/data`，`SERVER_ROOT = Path(__file__).resolve().parents[3]`）。已加入 `.gitignore`。图片落 `data/uploads/<album_id>/<image_id>.<ext>`，缩略图 `<image_id>.thumb.webp`。
- **时间以 ISO 8601 字符串入库、不带时区**（本地时间），字典序即时间序，`ORDER BY` 直接可用。`now_iso()` 用微秒精度保证排序稳定。
- **批注坐标归一化（0~1）**。矩形批注的 `(x, y)` 是**拖拽起点**（序号落点），`w/h` **带符号**（向左上拖为负）。因此 Pydantic 里 `w/h` 的约束是 `ge=-1, le=1` 而不是 `ge=0`。矩形范围 = `min(x, x+w)` 起、`|w|×|h|`。
- **seq 统一编号**：新增取 `COALESCE(MAX(seq),0)+1`（限本图集）；删除后 `_compact_sequence()` 重排为 1..N。删图片时先 `delete_image_annotations()` 压实再删图。
- **原图按上传字节原样保存**（不二次编码，避免 JPEG 损失）；缩略图转 WebP（无 WebP 编码器时退回 JPEG），透明铺白底。
- **EXIF**：`ImageOps.exif_transpose` 取旋转后的尺寸入库，与浏览器渲染尺寸一致，否则批注会错位。
- 服务层只抛 `NotFoundError`/`ValidationError`，在 `main.py` 注册处理器映射为 404/400，服务层不 import FastAPI。
- 上传接口返回 `{saved, failed}`，单文件失败不影响整批。
- `main.py` 加 `lifespan` 调 `init_db()`（建表幂等）。
- **FastAPI 文件参数用 `Annotated[list[UploadFile], File()]`** 而非 `= File(...)`，否则 ruff 的 B008 报错。

### 前端（src/）

新增：`api/{request,album,index}.js`、`stores/album.js`、`utils/datetime.js`、`views/{AlbumsView,AlbumDetailView}.vue`、`components/album/{AlbumFormDialog,ImageStage,ThumbnailStrip}.vue`；`vite.config.js` 接入 `/api` 代理；`routes.js` 加 `/albums` 与 `/albums/:albumId`；`MainLayout.vue` 支持 `meta.activeMenu`（详情页高亮父菜单）与 `meta.parent`（可点击面包屑）；`icons.js` 补 18 个图标。

关键设计：

- **`ImageStage.vue` 是核心**：按图片原始宽高比在容器内等比内缩算出精确渲染矩形 `box`，把 `<img>` 与批注层贴到**同一个 box**（实测 `sameBox: true`，宽高比一致）。这样批注不会漂移。`ResizeObserver` + `@load` 触发重算。
- 指针交互用 `pointerdown/move/up` + `setPointerCapture`；点批注要求位移 < 0.02 才算单击（防误触），矩形要求 `|w|,|h| >= 0.012`。
- 图片与批注层都用 `object-fit: contain`，保证图片**绝不被拉伸变形**。
- 说明编辑框用绝对定位贴在序号图标旁，`x > 0.58` 自动左翻、纵向按 `canvasSize` 夹紧。
- 选中态由父组件 `selectedId` 驱动；**ImageStage 内用单个 watcher 同时盯 `[image.id, selectedId]`** —— 拆成两个 watcher 会在「从清单跳图并选中」时把刚打开的编辑框又关掉。
- 上传三路：剪贴板 `paste`（监听 window，输入框内不抢）、文件选择（隐藏 input）、拖拽。共用 `upload()`。
- **CSS 变量：Naive UI 用的是 `--n-` 前缀且部分变量动态生成**（`--n-text-color-3`、`--n-primary-color` 等 grep 不到字面量）。因此业务样式改用自己在 `src/styles/index.css` 定义的语义变量 `--tl-board/--tl-surface/--tl-surface-border/--tl-text-muted/--tl-text-dim/--brand-primary`，按 `html[data-theme]` 切换；批注强调色 `--anno-accent: #f59e0b` 不随主题变（叠在截图上，需在浅底/深底 K 线图上都醒目）。
- 图集列表的封面地址由后端 `_decorate()` 拼好（`cover_url` / `cover_thumb_url`），前端不硬编码接口路径。
